# الصفحة الرئيسية الموحَّدة — إيبيكس سورس

Next.js (App Router) + TypeScript + Tailwind CSS، عربي/RTL بالكامل. صفحة تعريفية عن المنصة + دخول موحَّد واحد + تسجيل عميل جديد، يحوّل تلقائياً للبوابة الصحيحة (`web-customer`/`web-supplier`/`web-admin`) بعد الدخول.

## التشغيل

```bash
cp .env.example .env.local   # عدّل API_URL وروابط البوابات الثلاث إن لزم
pnpm --filter @apex/web-landing dev -p 3004
```

يتطلب تشغيل `apps/api` (على المنفذ 3000) والبوابات الثلاث (3001/3002/3003) لتحويل الدخول الموحَّد إليها فعلياً.

## البنية

- **لا جلسة خاصة به إطلاقاً** — هذا التطبيق لا يُصدر أي كوكي جلسة، فقط ينسّق تسليم الجلسة للبوابة الصحيحة.
- `src/actions/auth.ts` — `unifiedLogin()` يحاول تسجيل الدخول الحقيقي في الأنواع الثلاثة (عميل/مورد/إدارة) بالتوازي بنفس البيانات؛ `registerCustomer()` تسجيل عميل جديد (دائماً عميل — لا تسجيل ذاتي لمورد/إدارة).
- `src/lib/portals.ts` — روابط البوابات الثلاث (`CUSTOMER_PORTAL_URL`/`SUPPLIER_PORTAL_URL`/`ADMIN_PORTAL_URL`) + بناء رابط `/sso?code=...` للتحويل.
- `src/lib/api.ts` — عميل fetch نحيف، بلا كوكي (لا جلسة هنا).

## آلية التسليم (SSO handoff)

3 بوابات على 3 أصول منفصلة تماماً لا تشترك بكوكي — التحويل يمر عبر رمز تسليم لمرة واحدة صالح 60 ثانية فقط (`sso_handoff_code` في الباك-إند)، لا عبر أي JWT/refresh token حقيقي في رابط المتصفح. كل بوابة تستبدله بجلسة حقيقية عبر `src/app/sso/route.ts` الخاص بها (نداء خادم-لخادم لـ`POST /auth/sso/consume`).

إن كان نفس البريد مسجَّلاً بأكثر من صفة (عميل ومورد معاً مثلاً)، تُعرض شاشة اختيار صريحة بدل التخمين.
