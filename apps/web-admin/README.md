# بوابة الإدارة — إيبيكس سورس

Next.js (App Router) + TypeScript + Tailwind CSS، عربي/RTL بالكامل، تغطي كل إجراءات الإدارة عبر دورة حياة الطلب بأكملها ضد `apps/api`: مراجعة الطلبات، المزايدة وسعر الصرف، فحص المورد الخارجي، التحقق من الدفعات (four-eyes)، اللوجستيات والجمارك، النزاعات والتصعيدات والتجديدات، وإدارة الحسابات.

## التشغيل

```bash
cp .env.example .env.local   # عدّل API_URL إن لزم (افتراضياً http://localhost:3000)
pnpm --filter @apex/web-admin dev -p 3003
```

يتطلب تشغيل `apps/api` (مهاجَرة) على المنفذ 3000. **لا صفحة تسجيل ذاتي** — أول حساب `ADMIN_OWNER` يُنشأ عبر `pnpm --filter @apex/api seed:admin`.

## البنية

- `src/lib/state-labels.ts` — `getAdminAction(orderId, state, holdType)` هو أكبر جدول action-map في المشروع (الإدارة تتدخل في كل مرحلة تقريباً)، مقسَّم لدوال فرعية حسب عائلة الحالة (مراجعة/فحص/مزايدة، عقد/دفعات، لوجستيات/جمارك، نزاعات، تصعيد، تجديد) بدل دالة `switch` ضخمة واحدة.
- `src/lib/approver-picker.ts` — منطق تصفية المعتمِد المؤهَّل لكل إجراء four-eyes (الأدوار المسموحة، واشتراط اختلاف الدور للاسترداد الإلزامي).
- `src/lib/orders.ts` — `getOrderDetail` يستدعي `/orders/:id/detail-for-admin` (أشمل قراءة — تشمل PII العميل والموردين المرشَّحين وحالة اعتماد four-eyes)، بالإضافة إلى `listAll`/`listNeedsAdminAction`/`getAuditLog`.
- `src/lib/accounts.ts` — `getMe`/`listAdmins`/`listSuppliers`.
- `src/app/(portal)/dashboard` — قائمة "طلبات جديدة" (بانتظار تأكيد العربون) + قائمة "تحتاج إجراءً إدارياً" مُصنَّفة حسب الفئة (مراجعة/فحص/مزايدة/تحقق دفعات/لوجستيات/جمارك/نزاعات/تصعيدات/تجديدات) + رابط بحث عام.
- `src/app/(portal)/accounts` — سرد/إنشاء/تعطيل/تفعيل حسابات الإدارة والموردين (الأزرار تُخفى محلياً حسب الدور، والتنفيذ الفعلي محمي في الباك-إند دوماً).
- `src/app/(portal)/orders/[orderId]/` — صفحة مركزية شاملة (بيانات العميل والمورد كاملة، القيمة المالية، خطة الدفع، رسوم التخليص، النزاعات/التصعيدات/التجديدات، السجل الزمني، **وسجل التدقيق الفعلي** Audit Log) + صفحات مخصَّصة لكل مجال إجراء: `review`, `vetting`, `bidding`, `payment-plan`, `payment-verification`, `logistics`, `customs`, `dispute`, `dispute/new`, `mandatory-refund`, `escalation`, `renewal`.

### نمطا four-eyes (لا نمط واحد عام)

- **نمط "رشّح ثم اعتمد"** (`payment-verification`, `vetting`, `mandatory-refund`): إن لم يوجد ترشيح معلَّق تظهر قائمة اختيار معتمِد مؤهَّل (تستبعد نفسك دوماً، وتستبعد من يشارك دورك في حالة الاسترداد الإلزامي)؛ إن كان الترشيح لشخص آخر تظهر رسالة انتظار باسمه؛ إن كان الترشيح لك يظهر زر الاعتماد.
- **نمط "اعتماد مباشر"** (`customs`): لا ترشيح مسبق — أي أدمن آخر مؤهَّل (غير من أنشأ الرسم) يمكنه الاعتماد مباشرة، لأن `customs-fees.service.ts` في الباك-إند نفَّذها بهذا الأسلوب المختلف عمداً.

الجلسة عبر كوكي httpOnly (`apex_admin_token`) تُعيَّن من داخل Server Actions مباشرة — التوكن لا يصل لجافاسكربت المتصفح إطلاقاً.
